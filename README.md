*ГРУЗСПЕЦСЕРВИС*

Сайт сервиса грузовой техники. На нём можно посмотреть услуги, рассчитать примерную стоимость выезда, оставить личную или корпоративную заявку и связаться с консультантом.

Интерфейс сделан на HTML, CSS и JavaScript, серверная часть — на FastAPI. В рабочей версии данные хранятся в Supabase, а при локальном запуске — в SQLite.
Быстрый запуск
Понадобится Python 3.12 или новее. Откройте PowerShell в папке проекта и выполните команды по очереди:
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Файл .env уже подготовлен. Для нового клона создайте его из шаблона:
# Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
Затем откройте http://localhost:8000.

В режиме APP_ENV=development сайтом можно пользоваться и без API-ключей. Заявки сохраняются локально в data/local.db, а на сайте будет показано, что заявка сохранена только на этом компьютере. Карта, отзывы и контакты станут доступны после настройки. Без ключа ИИ консультант сможет подсказать, как устроены разделы сайта.

Если не хотите, чтобы тестовые заявки отправлялись в подключённые каналы, оставьте соответствующие ключи пустыми.
Настройки .env
В файле .env хранятся контакты компании и параметры подключённых сервисов.
Переменные	Для чего нужны
COMPANY_PHONE, COMPANY_ADDRESS, COMPANY_EMAIL	Контакты, которые увидят посетители. Если телефон не указан, сайт покажет заглушку.
COMPANY_LATITUDE, COMPANY_LONGITUDE	Координаты СТО. Они нужны для карты и расчёта расстояния.
TELEGRAM_URL, MAX_URL	Ссылки на Telegram и MAX. QR-коды сайт создаёт автоматически.
SUPABASE_URL, SUPABASE_KEY	Адрес Supabase и серверный ключ service_role. Этот ключ нельзя передавать в браузер.
TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID	Токен бота и ID чата, куда отправлять заявки.
TELEGRAM_WEBHOOK_SECRET, PUBLIC_URL	Секрет для проверки webhook и публичный HTTPS-адрес сайта.
TELEGRAM_MANAGER_IDS	Необязательные Telegram ID менеджеров, которым доступна кнопка «Оформлено». Несколько ID указываются через запятую.
MAIL_TRANSPORT=resend, RESEND_API_KEY, SMTP_FROM, MANAGER_EMAIL	Отправка почты через Resend. Этот способ подходит для Render Free.
MAIL_TRANSPORT=smtp, SMTP_*	Альтернативная отправка через SMTP с TLS, если хостинг разрешает такие подключения.
DEEPSEEK_API_KEY, DEEPSEEK_MODEL	Ключ и название модели для ИИ-консультанта.
YANDEX_MAPS_API_KEY	Ключ JavaScript API Яндекс Карт. Ограничьте его доменом сайта.
YANDEX_ROUTING_API_KEY	Серверный ключ Matrix API для расчёта расстояния по дорогам.
YANDEX_ORG_ID	Числовой ID организации на Яндекс Картах для показа официальных отзывов.
COMPANY_YEARS	Подтверждённый стаж компании. Если оставить поле пустым, сайт его не покажет.


Для Matrix API и JavaScript API Яндекс Карт могут потребоваться отдельные подключения или тарифы. Доступные функции и квоты зависят от условий Яндекса.

YANDEX_ORG_ID — это число в ссылке на карточку организации, а не API-ключ. Отзывы загружаются с официальной страницы Яндекса: сайт не собирает и не добавляет оценки самостоятельно.

Координаты указывайте через точку. Если координаты СТО пока неизвестны, оставьте обе переменные пустыми или закомментируйте их. Не используйте демонстрационные координаты как настоящий адрес компании.
Подключение Supabase
1. Создайте проект в Supabase.
2. Откройте SQL Editor → New query.
3. Вставьте содержимое файла migrations/001_supabase.sql и нажмите Run.
4. Добавьте URL проекта и серверный ключ service_role в .env или в настройки Render.
SQL-файл создаёт таблицы заявок и уведомлений, служебные функции и закрытое хранилище order-photos. Публичный ключ anon здесь не подойдёт: доступ к таблицам закрыт политиками RLS и правами.

Количество завершённых заявок сайт получает из базы. Кнопка «Оформлено» в Telegram меняет статус заявки на completed. Тестовые заявки из локального запуска в Supabase не попадают.
Публикация на Render Free
В проекте уже есть Dockerfile и render.yaml. Создайте Render Blueprint из корня репозитория или настройте Web Service с Docker. Для Web Service оставьте Root Directory пустым, задайте Dockerfile Path как `./Dockerfile`, а Docker Build Context Directory как `.`. Не указывайте `content` в качестве Root Directory: это каталог с текстом политики конфиденциальности, а не корень приложения. Переменные окружения перечислены в .env.example. Для production задайте:
- APP_ENV=production
- PUBLIC_URL=https://ваш-сервис.onrender.com
Файл .env не добавляется в Git и не попадает в Docker-образ.

У Render Free файловая система временная, а сервис может засыпать без посетителей. Поэтому база хранится в Supabase. Фотографии заявок временно сохраняются и в закрытом Supabase Storage: так их можно повторно отправить, даже если сервис перезапустился. После доставки заявки в Telegram и по почте временные копии удаляются.

Render Free блокирует исходящие SMTP-порты 25, 465 и 587. Поэтому для почты по умолчанию используется Resend через HTTPS.

Для теста Resend без собственного домена укажите:
- SMTP_FROM=onboarding@resend.dev
- MANAGER_EMAIL — адрес, на который зарегистрирован аккаунт Resend
В этом режиме письма можно отправлять только на адрес аккаунта. Чтобы использовать другие адреса, подтвердите собственный домен в Resend. На другом тарифе или хостинге можно переключиться на SMTP через настройки SMTP_*. Также учитывайте ограничения и квоты почтового сервиса.

При каждом запуске в production приложение само регистрирует Telegram webhook. Для этого в Render должны быть заданы PUBLIC_URL, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и TELEGRAM_WEBHOOK_SECRET.

Webhook можно зарегистрировать вручную или использовать скрипт для диагностики:
.\.venv\Scripts\python.exe scripts/register_webhook.py
Бот должен состоять в нужном чате и иметь право отправлять и удалять сообщения. Webhook проверяет секретный заголовок, ID чата и, если список настроен, ID менеджера.

Когда менеджер отмечает заявку завершённой, бот удаляет связанные сообщения, фотографии и геометку. Telegram может запретить удаление старых сообщений. В таком случае бот заменит кнопку отметкой о завершении, а статус заявки всё равно сохранится в базе.

Настройка Docker доверяет заголовкам внешнего прокси Render. Если будете размещать приложение самостоятельно, ограничьте параметр --forwarded-allow-ips адресами своего прокси.
Как рассчитывается стоимость
Тарифы и коэффициенты хранятся в config/pricing.json. Перед публикацией проверьте и замените стартовые значения на актуальные. Итоговую сумму сервер рассчитывает заново и сохраняет в заявке.
- Стоимость работ — базовый тариф услуги, умноженный на коэффициент типа транспорта.
- Выезд стоит 10 000 ₽. В эту сумму входят первые 20 км от СТО; каждый следующий километр в одну сторону — 80 ₽.
- Для срочной заявки предварительная сумма умножается на 1,2.
- Если доступен Matrix API, для расчёта берётся расстояние по дорогам. Если API недоступен — расстояние по прямой умножается на 1,3, а результат помечается как оценочный.
- Пока расстояние неизвестно, сайт не считает его нулевым, а сообщает, что путь ещё не учтён.
- Стоимость запчастей и поездок дальше 500 км согласуется отдельно. Подать заявку можно из любого региона.
- Для корпоративных заявок калькулятор не используется.
Если измените формулу расчёта, обновите и пояснение на сайте. Предварительная сумма не заменяет диагностику, согласование маршрута и окончательное предложение менеджера.
Что происходит после отправки заявки
Формы отправляют данные на /api/orders или /api/corporate-orders. Вместе с заявкой можно прикрепить до пяти фотографий. Для защиты от случайного повторного создания заявки используется заголовок Idempotency-Key: форма создаёт его сама и повторяет запрос с тем же ключом при сетевом сбое. Если пользователь изменит данные, будет создан новый ключ.

Сначала сервер проверяет заявку и сохраняет её в базе. Затем создаёт задания на отправку уведомлений и временно сохраняет фотографии. Telegram и почта получают данные из одной записи в базе. В письмо входят текст заявки, JSON и фотографии; Telegram получает текст, геометку, фотографии и кнопку «Оформлено».

Если один канал временно недоступен, заявка не пропадает, а второй канал продолжает работать. Фоновый процесс повторяет неудачные отправки с задержкой — до одного часа.

Сообщение об успешной отправке в браузере означает, что заявка сохранена и поставлена в очередь. Оно не гарантирует, что Telegram и письмо уже доставлены. В production приложение ожидает, что оба канала настроены. Если исправить настройки и перезапустить сервис, фоновый процесс продолжит отправку.

Фотографии проверяются по содержимому, очищаются от метаданных, переводятся в JPEG и уменьшаются до 1920 пикселей. Исходные имена файлов не сохраняются. Если загрузить фотографию не удалось, заявка не будет отправлена частично. Форму можно отправить повторно с тем же ключом, пока выбранные фотографии остаются в ней. Если закрыть форму, неудачно загруженный файл восстановить нельзя.

Сторонние сервисы не всегда могут гарантировать однократную доставку: например, соединение может оборваться после отправки, но до получения подтверждения. Resend использует Idempotency-Key. Telegram сохраняет прогресс отправки частей заявки, но в редких случаях на границе ответа возможен повтор. Один фоновый процесс рассчитан на один бесплатный экземпляр Render.
Перед публикацией сайта
Замените текст в content/privacy.txt на реквизиты и условия вашей организации. Сейчас там только подготовленный шаблон, а не готовый юридический документ.

Проверьте требования к хранению и размещению персональных данных для Supabase, Telegram, почты и ИИ-сервиса. Также заранее определите, как долго будут храниться заявки и как их удалять. Пока в настройках нет реальных контактов и реквизитов, сайт подходит только для локальной демонстрации.
